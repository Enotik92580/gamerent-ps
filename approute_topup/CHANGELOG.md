# AppRoute Top-Up 1.1.0: что исправлено

Плагин обновляется заменой файла `AppRouteTopUp_LuckyFunpay.py` и перезапуском бота (`/restart`).
База `storage/plugins/approute_topup/topup.sqlite3` переносится автоматически, удалять её нельзя.

## Деньги и защита аккаунта

- **Выбор из списка.** Если покупатель пишет число, сначала ищется точное значение варианта и только потом номер в списке. Раньше при вариантах `0, 1, 2` ответ «1» отправлял сервер `0`.
- **Нет частых запросов к FunPay.** На паузе («Статус» 🔴) и в очереди за предыдущим заказом покупателя заказ раньше запрашивался у FunPay каждую секунду. Теперь проверка идёт раз в 20–60 с.
- **Одна валюта для цены и закупки.** Автоцена и покупка выбирают валюту по одному правилу: лот → валюта поставщика → общая валюта (только для Steam) → не отправлять. Раньше цена могла считаться в USD, а пополнение уходить в RUB.
- **Временные ошибки повторяются.** При сбое сети, ответе FunPay или AppRoute с ошибкой 5xx заказ повторяется с растущей паузой (15 с … 10 мин, до 6 раз), а не сразу уходит на ручную проверку. Последняя ошибка видна в карточке заказа.
- **Пауза 429 до отправки.** Если пауза по лимиту запросов сохранена заранее, запрос оплаты не уходит. Теперь такая операция больше не считается «отправленной с неизвестным результатом»: заказ возвращается в очередь и оплачивается позже с новой проверкой. Операции `unsent` из версии 1.0.0 обрабатываются так же.
- **Отдельный поток для обслуживания.** Обновление цен, каталога и действия панели с лотами идут в отдельном потоке и больше не задерживают ответы покупателям.
- **Интервал цен не меньше 20 минут.** Меньшее значение заменяется на 20.

## Логика заказа

- **Подтверждение аккаунта** («Это ваш аккаунт?») задаётся, только если поставщик вернул ник. Раньше бот спрашивал «Найден аккаунт: <ваш же UID>», а без ответа заказ уходил на ручную проверку. Ответы «Да.», «да, мой», «+», «не мой» теперь распознаются.
- **Нумерация шагов** совпадает с приветствием: не будет «ответьте на 1 вопрос», а потом «Шаг 2 из 2».
- **Неиспользуемые шаблоны теперь отправляются:** `paused`, `amount_range` (выход суммы за границы и срабатывание предохранителя), `missing_form`, `optional`, `resumed`.
- **Причина возврата.** При авто-возврате покупатель сразу получает причину (товар недоступен, нет баланса), а `{refund_note}` гласит «Средства будут возвращены автоматически».
- **Повтор возврата.** Если FunPay не ответил на запрос возврата, бот проверяет статус заказа и повторяет запрос до 3 раз, пока заказ ещё оплачен.
- **Отказ поставщика по данным при предпроверке** (400/422 с указанием поля) теперь запускает повторный ввод, а не ручную проверку. Покупатель видит, какое поле не принято.
- **Сообщение не повторяется бесконечно.** Если поле, о котором шёл вопрос, пропало из формы, бот задаёт следующий вопрос, а не обрабатывает сообщение по кругу.
- **Ник Telegram.** Другое написание ника (с @ или без) снова пробуется после каждого нового ввода. TON-адреса не проверяются как username.
- **Заказ возвращён или закрыт на FunPay во время диалога** — диалог закрывается, продавец получает уведомление.
- **«➕ Обработать заказ»** (Заказы): ставит в работу заказ по номеру или ссылке. Подходит для заказов, оплаченных, пока бот был выключен, и пропущенных до привязки лота.
- **Данные, присланные сразу после оплаты** (до первого вопроса), не теряются: они становятся ответом на первый вопрос.
- **Совместимость с FunPayAPI.** Заказы без атрибута `currency` больше не отклоняются. Данные покупателя и условия читаются также из `lot_params`/`buyer_params` и `full_description`. Лоты подходят, если у заказа не указана подкатегория.
- **Баланс** принимается в USD или USDT.

## Хранилище и производительность

- Состояние, время следующей обработки и чат заказа хранятся в индексируемых колонках. Обработчик не перечитывает весь журнал каждую секунду. Старая база переносится при первом запуске.
- Метки обработанных сообщений старше 7 дней удаляются. Сообщения из чатов без активного заказа не записываются в базу.
- Если FunPay 10 раз подряд не принял сообщение покупателю, отправка прекращается, а продавец получает уведомление.
- Отчёт об ошибках обновления лотов приходит, только когда список ошибок изменился.
- Повторное нажатие на экран больше не присылает дубль меню («message is not modified»).

## Панель

- После добавления лота сразу открывается **🎯 Автоподбор** по названию. Номиналы показываются с ценой в ₽ (по вашему курсу и наценке) и значком 🚫, если товар недоступен.
- **🧩 Фикс. поля** — экран со всеми полями формы (📌 задано / 🔢 сумма / ❓ спросим). Нажмите поле и отправьте значение.
- Ручная привязка принимает `product_id:item_id` и вариант через пробел. После привязки показывается сводка: цена, вопросы покупателю, подсказка про сумму.
- При перепривязке фиксированные поля сохраняются, если они есть в новой форме. Настройки суммы сбрасываются, только если у нового товара нет произвольной суммы.
- «♻️ Перечитать» перезаписывает условия определения заказа с FunPay.
- Условия, введённые вручную, принимают варианты через `/` и разделение запятыми.
- Валюта суммы выбирается кнопками (RUB/USD/KZT/UAH, «Не отправлять», «Как у поставщика»).
- В меню «Сумма» видны пример расчёта для 3 шт. и границы. Есть кнопка «♻️ Вернуть общую настройку».
- В список лотов добавлена кнопка «▶️ Включить отключённые» для лотов, отключённых плагином.
- В Заказах появился фильтр «🛠 Ждут продавца».
- Чат можно убрать из уведомлений.
- Уведомления о заказах приходят с кнопками «Заказ FunPay» и «Покупатель», о смене цены — с кнопкой «Открыть лот».
- Устаревшая форма ввода больше не перехватывает сообщения. Другие команды бота во время ввода работают.
- В экспорте журнала скрыты пароли и токены, в том числе в копии запроса к поставщику.
- Подстановки из руководства (`{label}`, `{total}`, `{error}`, `{attempt}`, `{max_attempts}`, `{done}`, `{count}`) работают в шаблонах наравне со старыми.

## Что поправить в руководстве продавца

Код оставлен таким, как ниже. Значения по умолчанию не менялись, чтобы у работающих продавцов не изменились регион и цены.

| Пункт руководства | Как работает плагин |
|---|---|
| Регион по умолчанию IO | **RU** |
| Наценка по умолчанию 20% | **15%** |
| Лимит на заказ 20 | **50** |
| Порог низкого баланса 30 | **3 USD** |
| Подтверждение аккаунта выключено | **включено**, но вопрос задаётся только при нике от поставщика |
| «Фиксированная сумма — независимо от количества» | **Сумма за 1 шт. × количество**: покупатель платит за каждую штуку. Иначе при покупке 3 шт. он получил бы сумму за одну |
| Режим «Спрашивать сумму у покупателя» | **Не реализован намеренно**: сумма всегда считается из оплаченного количества |
| Цена Steam считается сама | Для произвольной суммы нужна **«База цены»** (номинал, которому соответствует цена API) |
| Диалоги пропадают после `/restart` | **Сохраняются** в базе |
| История — только успешные | В журнале **все** обслуживаемые заказы, есть фильтр «Ждут продавца» |
| Структура меню (Статус, Доступ к API, Лоты…) | Главная → Витрина / Заказы / Финансы / Настройки |
