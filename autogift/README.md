# 🎁 AutoGift 6.3.0 — Telegram Gifts за Stars через FunPay Cardinal

Плагин для FunPay Cardinal. Он принимает оплаченный заказ, узнаёт у покупателя Telegram-ник, выбирает аккаунт с достаточным балансом Stars и отправляет подарки. Каждый подарок записывается в журнал выдачи.

Файл плагина: `AutoGift_LuckyFunpay.py`. Положите его в папку `plugins` Cardinal, включите в `/menu → Плагины` и выполните `/restart`.

## Что изменено в 6.3.0

### Надёжность выдачи
- **Подтверждение не истекает посреди выдачи.** Раньше 10-минутный срок подтверждения проверялся перед каждым подарком. Длинный набор обрывался на середине и попадал в «Проверку». Теперь срок проверяется один раз, когда покупатель пишет «+».
- **Выдача больше не блокирует Cardinal.** Заказы и сообщения покупателей обрабатываются в отдельном потоке. Выдача идёт по очереди в своём потоке. Пока отправляются подарки, остальные чаты, автоответы и плагины работают.
- **Постоянные подключения к Telegram.** Раньше на каждый подарок и каждую проверку баланса создавалось новое соединение. Теперь у каждого аккаунта одно постоянное подключение на всё время работы. На весь заказ ник ищется один раз. Меньше FloodWait и подозрений Telegram к сессиям.
- **Переключение аккаунтов.** При FloodWait, нехватке Stars или обрыве связи до оплаты остаток набора досылается с другого подходящего аккаунта. Подарок с неизвестным итогом оплаты (таймаут) повторно не отправляется.
- **Защита лотов без «мигания».** Один неудачный запрос к Telegram больше не ставит все лоты на паузу. Если балансы недоступны, пауза включается только после 3 неудачных проверок подряд. Лоты включаются обратно только при свежем каталоге.
- **Пропущенные заказы подхватываются.** Раз в 5 минут, а также при включении выдачи плагин проверяет оплаченные заказы за последние 48 часов. Так обрабатываются заказы, оплаченные при выключенной выдаче, во время перезапуска или при сбое FunPay.
- **Ничего не теряется молча.** Если оплаченный заказ с меткой AutoGift не совпал с привязкой (лот изменён или скопирован), админ получает уведомление с кнопкой «🔁 Принять этот заказ». Покупатель получает ответ, даже если прислал что-то непонятное.
- **Отозванная сессия.** Если Telegram завершил сессию аккаунта, приходит уведомление с просьбой добавить аккаунт заново.

### Покупатель
- Ник принимается в форматах `@username`, `t.me/username`, `https://t.me/username`. При включённом подтверждении принимается и просто `username`.
- Сценарий: ник → бот показывает получателя → покупатель пишет `+` → заказ встаёт в очередь. Подтверждение можно выключить в «⚙️ Настройки → 👤 Покупатель». Тогда выдача начинается сразу после проверки ника.
- Возврат до отправки: `!вз`, `!бэк`, `!refund` (или `!вз НОМЕР`, если заказов несколько).
- Если в одном чате несколько заказов: `+ НОМЕР`, `- НОМЕР`, `!gift НОМЕР @username`.
- Ник из поля заказа FunPay («Telegram Username», «Username», «Ссылка на профиль») подставляется автоматически.
- Напоминание через 5 минут приходит и тем, кто прислал ник, но не подтвердил его.

### Админ
- **«🟠 Проверка»** теперь с действиями по каждому заказу:
  - отметить подарки с неизвестным результатом как отправленные или неотправленные;
  - «🔁 Продолжить выдачу» (или «👤 Запросить ник у покупателя»);
  - «✅ Выдано вручную»;
  - «↩️ Вернуть деньги».
- Добавление аккаунта по номеру:
  - код вводится через пробелы, при ошибке можно ввести его снова (до 3 попыток);
  - на каждый шаг 5 минут;
  - понятные сообщения об ошибках;
  - сообщения с номером, кодом и паролем удаляются из чата.
- Session String проверяется входом через прокси. Аккаунт получает имя, дубли не создаются.
- Кнопки «🚫 Отмена» во всех окнах ввода. Удаление аккаунта и лота спрашивает подтверждение. Лот с активными заказами удалить нельзя.
- Шаблоны сообщений проверяются при сохранении, после сохранения показывается превью. Поддерживаются и переменные из старой инструкции: `{tg_user}`, `{tg_user_at}`, `{total_sent}`, `{amount}`, `{gift_types}`, `{star_cost}`, `{total_stars}`, `{price}`, `{buyer_id}`.
- Новые настройки: «🔢 Лимиты» (единиц, подарков и Stars на заказ), «🔔 Напоминание», «💸 Возврат командой», «➕ Подтверждение».
- Если тот же ID лота добавить повторно, набор подарков заменяется, а старый тег сохраняется. Нецифровые строки в списке Gift ID игнорируются.
- Смена прокси или API-ключей применяется автоматически: аккаунты сами переподключаются при следующем запросе.

### Хранилище
- Раз в 10 минут сохраняется копия каждого файла (`*.bak`). Повреждённые настройки, аккаунты и лоты восстанавливаются из неё. Журнал заказов из копии **не** восстанавливается: старая копия может показать отправленный подарок как неотправленный.
- Журнал записывается раньше настроек. Если сбой случится между двумя записями, следующий запуск не заблокируется.
- Завершённые заказы старше 60 дней переносятся в `autogift_orders_archive.jsonl`. Статистика «за всё время» и CSV-экспорт их учитывают.

## Что осталось как было
- Привязка лота по тегу `[AutoGift:…]` в подробном описании. Тег защищает от выдачи по чужому или скопированному лоту. После правки описания нажмите «Проверить тег».
- Каталог из 11 обычных подарков. Цены подтверждаются Telegram перед каждым заказом.
- Перед каждой оплатой цена платёжной формы сверяется с каталогом, а ник — с подтверждённым ID получателя.

## Тесты

```bash
python -m venv .venv && .venv/bin/pip install pyTelegramBotAPI Kurigram==2.2.26 pytest
.venv/bin/python -m pytest autogift/tests
```

Тесты используют настоящие telebot и Kurigram, а FunPayAPI и Cardinal заменены заглушками. Покрыты:
- выдача с переключением аккаунта при FloodWait, без повторной оплаты после таймаута;
- диалог с покупателем и возврат командой;
- защита лотов, хранилище, миграция журнала, повторная проверка пропущенных заказов;
- постоянные подключения;
- все кнопки меню.

Реальные Telegram и FunPay в тестах не используются. Перед запуском на рабочем аккаунте проверьте плагин на тестовом лоте с дешёвым подарком.
